# Init parity: OpenRC and systemd, both first-class

Owner rule (2026-11-13): "horcrux and patronus should fully, 100% support openrc and systemd. gentoo is about choice."
Before this change Horcrux was OpenRC-only in practice. This is the audit, what phase 1 landed, and the ordered plan.

## Phase 1
- `horcrux-api/src/init.rs`: `InitBackend` trait (start/stop/restart/enable/disable/state/is_enabled/exists), `OpenRcBackend`, `SystemdBackend`, runtime `detect()` (systemd iff `/run/systemd/system` is a directory and `systemctl` exists, else OpenRC). Commands go through a `CommandRunner`, so both backends are unit-tested with a recording fake.
- A systemd unit beside every OpenRC script shipped by Horcrux's ebuilds, same behaviour (same `/etc/conf.d` env file where the script has one); shared script where the initd held real logic (touchbar).
- Binhost: amd64/systemd tier 35 timed out three runs because `evolution` (-> webkit-gtk, hours) sat in it, starving tiers 36-41 and 90 (neovim, pahole, linux-firmware, gentoo-xcursors, nodejs never reached). Evolution moved to heavy tier `91-heavy-gnome-mail`; the heavy-only continuation chains while a run finishes a heavy tier. No new tier: the four lanes already exist. samba/avahi/bind per-lane coverage is documented in gentoo-binhost `docs/OPERATIONS.md` (official-binhost binaries count as covered; bind is never built in any lane).

## Ordered plan
1. Phase 2: remaining Rust call sites onto `init`; hogsmeade-tools unit after its OpenRC fix lands; exempt list to empty.
2. Phase 3: systemd live ISO, server first (live-* units, stage3 systemd rootfs, installer), then `live-iso-server-systemd-x86_64.yml` on rw-man-01 (KVM, one ISO build at a time; the aarch64 TCG lane stays OpenRC until x86 is green); GNOME/XFCE after.
3. Phase 4: docs and an INIT dimension in every edition's matrix.

## Phase 3: systemd live ISOs (2026-11-13)
Decisions:
- **The installed system runs the init of the ISO.** One download per edition x arch x init (`<product>-<edition>-<init>-<channel>-<arch>.iso`);
  the installer has no init switch (the target is a copy of the live root, and a switch would mean shipping both stacks in every image). The
  download pages offer both and list a systemd image only once its CI QEMU tests passed (the asset exists only after a passing run).
- **One implementation per live service.** `/etc/init.d/live-*` and `zram-swap` stay the code; their units call
  `/usr/libexec/live-openrc-compat <script> start|stop|exec`, which provides `einfo`/`ewarn`/`eend` and runs `start_pre` + `command` for the
  supervised `live-serial`. tty1: `live-installer` writes the agetty arguments to `/run/live-installer/tty1-args` (systemd) or inittab's `c1:`
  line (OpenRC); `getty@tty1` runs `/usr/libexec/live-getty-tty1` via the drop-in `00-live.conf`, which the installer removes.
- **Same initramfs on both inits.** systemd images build the script-based dracut initramfs (every `systemd*` dracut module omitted in
  `/etc/dracut.conf.d/05-init.conf`): dmsquash-live, zfs, the horcrux-unlock/tpm-unlock modules, their hooks and passphrase prompts behave
  identically; systemd starts as PID 1 after switch_root. `sys-kernel/installkernel -systemd` on both, so kernels are `/boot/vmlinuz-<ver>`
  (horcrux-be, GRUB and the installer rely on it).
- **Same network stack.** dhcpcd + iwd on both (journald replaces sysklogd on systemd); ZFS: `zfs-import-cache`, `zfs-mount`, `zfs-zed`,
  `zfs-import.target`, `zfs.target` enabled.
- **GNOME on systemd** uses profile `desktop/gnome/systemd`, upstream `gnome-session` and systemd-logind (no gnome-session-openrc, none of its
  patches); per-init USE in `variants/gnome-light/portage/package.use/init-{openrc,systemd}`. The desktop gates check PipeWire socket
  activation instead of the OpenRC start order. XFCE has no public download yet, so it has no systemd twin either.
- **CI load.** systemd twins run on a nightly slot (Horcrux 09:17/11:17 UTC x86_64, 09:47 aarch64; Patronus 13:17/13:47 UTC) and skip when
  the published systemd daily already is the current main commit (`common/ci-already-published.sh`); binpkgs are cached per arch+init
  (`binpkgs-<arch>-systemd`), distfiles and ccache are shared.
